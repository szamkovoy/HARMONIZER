# HARMONIZER: работа с документацией

Код — источник истины; `docs/` — каноническая карта приложения.

Перед задачей:
1. Прочитай `docs/00_index/MAP.md` и определи все затронутые модули, включая обе стороны взаимодействий.
2. Для каждого прочитай `docs/02_modules/<module>/spec.md` и `dependencies.md`.
   Для `remote-play` используй путь из MAP.
3. Проверь относящиеся к задаче пункты `docs/04_workspace/open_questions.md`.
4. Для UI и различий iOS/Android прочитай `docs/04_workspace/multiplatform_ui.md`.
   Используй существующие токены `modules/ui/theme.ts`.
5. Если обнаружился ещё один затронутый модуль, прочитай его документацию до изменения кода.

После изменения API, межмодульных зависимостей, БД, состава модулей или расхождения
с прежним описанием следуй `docs/03_rules/documentation_update_rules.md`:
точечно обнови spec/dependencies затронутых модулей, их history и общий CHANGELOG.
Нерешённые вопросы записывай в open_questions. Не описывай планы как реализованные возможности.

Автообновление документации запускает `.github/workflows/docs-sync.yml` после push
в `main` через Cursor CLI. Локальные hooks не нужны для этого механизма.
Не включай их как обязательный шаг: это может дублировать платные AI-запуски.
Автосинхронизация дополняет документацию задачи, но не гарантирует полную сверку приложения.

## Сборка и публикация приложения

По указанию Сергея от 2026-11-17 агент не запускает сборку iOS/Android и не загружает артефакты в сторы без отдельного прямого поручения. По умолчанию предложи Сергею выполнить сборку/загрузку самому и дай готовую команду. Просьба изменить код, номер версии или подготовить тест не является поручением собрать билд. При явно порученной сборке используй локальный EAS по правилам проекта. Маркетинговый номер общий для iOS/Android; номера сборок остаются отдельными, ими управляет EAS autoIncrement.

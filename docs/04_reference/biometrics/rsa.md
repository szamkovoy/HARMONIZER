# RSA

> **Реализация:** методика ниже задаёт полный разбор циклов и итоговую медиану по сессии; в приложении полный расчёт согласован с `runCoherenceSessionAnalysis` при **finalize**, а live-показ RSA во время практики опирается на укороченные оконные оценки по закрытым дыхательным циклам — см. `docs/02_modules/biofeedback/spec.md` и `CoherenceEngine` / `RsaEngine`.

## 9. Расчет Амплитуды RSA (Дыхательная синусовая аритмия)

Эта метрика оценивает «размах» сердечного ритма внутри дыхательного цикла. Она отражает гибкость вегетативной нервной системы.

### 9.1. Выделение дыхательных циклов

В точном соответствии с заданным ритмом дыхания (учти, то в зависимости от фазы практики он может быть разным — и ты это должен знать), мы анализируем данные `HR (Heart Rate)` в этих временных окнах.

### 9.2. Алгоритм расчета для каждого цикла

Внутри каждого окна (дыхательного цикла) находим:
- `HRmax` — максимальное значение пульса на вдохе.
- `HRmin` — минимальное значение пульса на выдохе.
- `RSAcycle = HRmax - HRmin`.

### 9.3. Очистка и усреднение

Чтобы исключить влияние случайных факторов (артефакты движения, зевок), применяем следующие правила:
- Используем те же сглаженные данные после медианного фильтра (окно 3 сек) из пункта 8.
- Итоговая амплитуда RSA за сессию (`RSAfinal`): берем медиану (не среднее арифметическое) всех значений `RSAcycle` за основную фазу практики. Медиана лучше отсекает случайные «выбросы».

Примечание: если `RSAcycle < 2` ударов в минуту, такой цикл может считаться «неактивным» (отсутствие дыхательного отклика), что полезно для внутренней диагностики качества сигнала.

### 9.4. Расчет Нормированной RSA

То есть дополнительно к тому, что выше расчитано в градусах, мы рассчитываем RSA ещё и в % (чтобы проще было анализировать статистику).

```text
RSA_relative = (RSAfinal / HRmean) * 100%
```

# Перенос одного ежедневного интенсива GetCourse → Гармонизатор

Прочитай эту инструкцию перед сбором, импортом и запуском теста. Для накопительных практикумов/курсов действует прежний `courses_migration_next_practicum_prompt.md`; не меняй её в этом чате.

## Данные этого переноса

- Название: **[Интенсив «…»]**.
- Шапка обоих писем: **приложенный файл**, центрировать, сохранить пропорции.
- Список уроков: **[URL]**.
- Список писем с фильтром И1…И7: **[URL]**.

Код и шаблон определи сам по названию; не задавай Сергею технических вопросов об этих полях:

| Интенсив | slug | templateKey |
| --- | --- | --- |
| Здоровье | intensive-health | health |
| Наслаждения | intensive-pleasure | pleasure |
| Сила | intensive-strength | strength |
| Любовь | intensive-love | love |
| Свобода | intensive-freedom | freedom |
| Мудрость | intensive-wisdom | wisdom |
| Святость | intensive-holiness | holiness |

Если передан файл `*.sources.json`, возьми название, slug, templateKey и оба URL из него; не проси Сергея вводить их повторно. Для «Здоровья» уже сохранён `content/intensives/health.sources.json`.

Нужно перенести только этот интенсив. Чужие прохождения, письма, покупки и настройки не менять. Исходники GetCourse только читать. Подготовка не разрешает отправку писем, commit/push или нативную сборку.

## А. Собрать авторский файл

Следуй AGENTS.md, прочитай карту и документацию courses. Реализация уже общая; новый интенсив не требует нового движка. Браузер используется **только для чтения GetCourse**. Не открывай и не разбирай воронки, интервалы, настройки отправки, статистику получателей или редакторы контента писем: нужные сведения находятся в двух переданных списках.

Готовые компактные DOM-экстракторы — `scripts/intensive-getcourse-extractors.mjs`. Используй нужную функцию в read-only browser evaluate. Возвращай только JSON с нужными полями; не печатай полные HTML/AX-деревья каждой страницы. Если условия экстрактора не выполнились — исследуй **эту** страницу, не угадывай пропущенный текст/видео.

Переиспользуй одну вкладку для уроков и одну для писем. После получения URL допускается пройти до пяти страниц за один вызов инструмента: переход → компактный экстрактор → следующий URL. Не анализируй каждый однотипный урок отдельным рассуждением и не открывай десятки новых вкладок. Извлечение DOM после каждого перехода служит проверкой текущей страницы; большие снимки нужны только для неожиданной ошибки.

1. `intensiveLessonIndex`: получить 30 URL в порядке списка. Сохранить порядок, в том числе у скрытых в GetCourse уроков. Открыть каждый URL и получить `intensiveVideo`: только Vimeo ID и источник. Не запускать видео и не переходить на Vimeo. Достаточно одного получения на страницу.
2. `intensiveMailingIndex`: получить ссылки «Практика 1»–«Практика 29». Письмо 30 не собирать: общий финальный текст уже сохранён. Обычно все 29 писем на первой странице; для И5/«Свободы» письмо 1 находится на второй. Переходить туда только за недостающим письмом, а не просматривать все страницы.
3. На каждой странице письма `intensiveAdvice(templateKey)` берёт только совет между «Совет дня:» и кнопкой урока; для `love` — до «Цитата:». Не переносить приветствие, цитату, кнопку, подпись и старую шапку. Шапка GetCourse может быть ошибочной — использовать только приложенную Сергеем.
4. Видео идут строго в порядке списка уроков. Советы допускается назначить по номеру письма 1–29: автор разрешил не сохранять соответствие совета конкретному видео. Нельзя повторять или пропускать советы.

Сохранить `content/intensives/<slug>.raw.json`:

```json
{
  "slug": "intensive-health",
  "title": "Интенсив «Здоровье»",
  "templateKey": "health",
  "lessons": [{"sourceUrl":"https://…","vimeoId":"123456789"}],
  "advice": [{"sourceNumber":1,"sourceUrl":"https://…","markdown":"Только текст совета"}]
}
```

В реальном файле — ровно 30 видео и 29 уникальных советов. Не писать новые тексты вместо авторских. Общий текст дня 30 и 14 авторских писем уже находятся в `content/intensives/templates/ru.json`; скрипт выберет нужные два. По прямому ответу Сергея **сохранить авторские тексты без смысловых исправлений**, включая упоминание ежедневных писем. Заголовки пунктов 1–7 уже выделены жирным. Пустые строки сохраняются.

```bash
node scripts/intensive-content.mjs review content/intensives/<slug>.raw.json content/intensives/<slug>.review.md
```

На этом этапе локальный файл шапки достаточно упомянуть в отчёте: генератор оставит «НЕ УКАЗАНА»/0×0, если CDN ещё не готов. Перед импортом заменить эти две строки в MD на реальный HTTPS URL и размер. Покажи Сергею ссылку на MD и числа «30 уроков / 29 советов / 2 письма», дождись его правок и команды продолжать. Не импортировать до утверждения.

## Б. Машинный импорт после авторской проверки

Перечитать последнюю версию MD. **Письма, цепочку и уроки записывать готовыми скриптами прямо в БД. Создавать/заполнять их через формы админки, клики или DOM-эмуляцию запрещено.** Не разрабатывать новый импортёр и не переписывать MD по памяти из чата.

Общую шапку разместить через существующий email CDN (при необходимости разрешён его интерфейс загрузки) и заполнить URL/размер в MD. Лендинг, сроки 90 дней и интервалы уроков не запрашивать: у интенсива фиксированный ежедневный режим и нет архива.

```bash
node scripts/intensive-content.mjs parse content/intensives/<slug>.review.md content/intensives/<slug>.json
node --env-file=.env.local scripts/intensive-translate.mjs content/intensives/<slug>.json
node --experimental-strip-types scripts/intensive-import-sql.mjs content/intensives/<slug>.json supabase/migrations/<новая_дата>_<slug>_content.sql
```

Если `.env.local` находится в другом штатном месте проекта — использовать его, не выводя секреты. Переводчик использует настроенный I18N_TRANSLATE_API или DEEPSEEK_API_KEY + AI_MODEL_STANDARD, сохраняет URL/переменные/переносы и общий кэш `content/intensives/translations`. Повторный запуск продолжает из кэша. Не переводить те же шаблоны заново в чате и не запускать полный i18n-sync приложения. Ошибка перевода останавливает импорт, не выдавать RU за переводы других локалей.

SQL требует RU+EN+DE+FR+IT+ES+PT+NL, создаёт ровно два email-step и 30 настоящих уроков. Уже записанные тексты сохраняются по умолчанию. `--replace-emails`/`--replace-lessons` — только после отдельного поручения заменить существующие правки. Старую применённую миграцию не переписывать.

Применить **эту новую миграцию** через штатный Supabase CLI к связанной БД. Сначала dry-run: не применять попутно чужие ожидающие миграции параллельных чатов. Не останавливаться на одном SQL-файле, если импорт уже поручен. После применения достаточно одной сводки: правильный slug, 30 уроков, два письма, ошибки нет. Не перечитывать всю базу/тексты/видео, не запускать тесты календаря/всего приложения для очередного содержимого. Проверку содержания делает Сергей.

```bash
node --experimental-strip-types scripts/intensive-test.mjs prepare <slug>
```

Сохранить полученный UUID. Подготовка не запускает ничего. Итог: «Импортирован интенсив, 30 уроков и два письма на восьми языках. Тест подготовлен, но не запущен». Не выполнять git add/commit/push до отдельного поручения.

## В. Минимальная проверка Сергеем

Только после отдельного «запускай» перечитать эту инструкцию и вызвать:

```bash
node --experimental-strip-types scripts/intensive-test.mjs start UUID --confirm-start
```

Это тест только для `sergei@zamkovoi.yoga`: оба письма отправляются подряд существующим runner, а стрелки в карточке позволяют открыть все 30 дней. Аккордеона нет. Реальный вебинарный пропуск тест не создаёт. Не запускать свою рассылку/цикл ожиданий, не использовать `course-test.mjs`, не очищать другие тесты.

Допустим один короткий status после небольшой паузы:

```bash
node --experimental-strip-types scripts/intensive-test.mjs status UUID
```

Если отправлено 2/2 и error=null — сообщить готовность, дальше проверяет Сергей. Если очередь ещё выполняется, сообщить текущий статус, cron продолжит сам. При конкретной ошибке проверить её, не отправлять всё повторно.

Когда Сергей явно скажет, что проверил и нужно отключить просмотр:

```bash
node --experimental-strip-types scripts/intensive-test.mjs finish UUID --confirm-finish
```

Стрелки исчезнут, **календарь начнётся заново с первого дня от этого момента** — так выбрал Сергей 19.11. Оба уже проверенных письма повторно не отправляются. Дальше виден только сегодняшний урок; последний закрывается в следующую местную полночь, вместе с доступом в Профиле. Повторный finish запрещён. «Проверил» не означает удаления теста/аккаунта или разрешения commit/push.

Механизм приложения уже общий: первая практика сразу, вторая по единому правилу 18:00, остальные в местную полночь; заключительное письмо в 07:00 дня 30, а не фиксированные +30 суток. Видео ru на русском интерфейсе, en на остальных языках тем же плеером/ТВ-путём, что у асан. Остальные курсы остаются русскими и сохраняют свой архив.

При очередном переносе только содержимого новая сборка не нужна, если установлен клиент с поддержкой интенсивов. Нативные сборки и загрузки делает Сергей. Не собирать приложение и не менять версию автоматически. После результата обновить статус/документацию точечно; сохранить и отправить изменения только по отдельной команде Сергея.

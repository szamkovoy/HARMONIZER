# Guard: автопродление SSL `harmonizer.zamkovoi.yoga`

**Читай этот файл в начале задачи**, если она затрагивает DNS, панель REG.RU (сайты / псевдонимы / редиректы / SSL), привязку домена в Vercel, смену публичного API-origin в приложении или откат РФ-прокси. На остальные задачи файл не открывать.

## Факты (канон на 2026-11-19)

| Что | Значение |
| --- | --- |
| Сертификат | Let's Encrypt, выпуск **HTTP-01**, панель REG.RU **автопродлевает** |
| Срок | с **2026-11-17** по **2027-02-15** (далее LE ~каждые 90 дней) |
| Имена в сертификате | `harmonizer.zamkovoi.yoga`, `www.harmonizer.zamkovoi.yoga` |
| DNS зоны | `ns1.hosting.reg.ru`, `ns2.hosting.reg.ru` |
| A / AAAA поддомена | `31.31.196.134`, `2a00:f940:2:2:1:1:0:147` (server147) |
| Трафик сайта | PHP `deploy/reg-ru-harmonizer-proxy.php` → Vercel |
| ACME | `/.well-known/acme-challenge/` — **только хостинг** (nginx/панель), **не** через PHP-прокси |

Подробности деплоя: `DEPLOY.md` → «Russia proxy».

## Перед рискованной операцией — предупреди пользователя

Если запрос подпадает под строку ниже — **остановись**, кратко объясни риск для SSL **и** для РФ-прокси, предложи безопасный вариант. Не выполняй молча.

| Запрос / действие | Что ломается |
| --- | --- |
| Вернуть `harmonizer` на **CNAME Vercel** (rollback из `DEPLOY.md`) | DNS уходит с REG.RU → автопродление панели и весь PHP-прокси для РФ |
| **Снова привязать** `harmonizer.zamkovoi.yoga` в проекте Vercel **и** сменить DNS под Vercel | Тот же эффект + письма «неверный домен»; в проде домен намеренно не на Vercel |
| Перенести DNS `zamkovoi.yoga` с `ns*.hosting.reg.ru` на сторонние NS без плана ACME | Автопродление на панели; возможны ручные TXT |
| Поменить **A/AAAA** поддомена на другой IP без синхронизации в разделе «Сайты» | HTTP-01 не дойдёт до server147 |
| Добавить **псевдоним сайта** на другой IP или несуществующий домен | Панель не продлит мультидоменный сертификат |
| **Редирект всего vhost** на другой домен (не только http→https на том же имени) | ACME-запросы не попадут на этот хостинг |
| Убрать исключение `/.well-known/` и пустить challenge в PHP→Vercel | Автопродление с высокой вероятностью упадёт |
| Сменить публичный origin (`EXPO_PUBLIC_COMMUNICATOR_API_URL`, `EMAIL_PUBLIC_BASE_URL`, `API_BASE` кабинета) **без** отдельного TLS/DNS-плана | Не ломает SSL напрямую, но отвязка от прокси = та же инфраструктурная опасность, что и DNS-откат |

Формулировки-триггеры в чате (неполный список): «перенеси DNS», «CNAME на vercel», «отвяжи от reg.ru», «другие NS», «Cloudflare для zamkovoi», «редирект на другой домен», «добавь домен в Vercel».

## Обычно безопасно для SSL (предупреждение не нужно)

- Правки `deploy/reg-ru-harmonizer-proxy.php` и выкладка на хостинг (если **не** трогаете rewrite для `/.well-known/`).
- Production-деплой Vercel, Supabase, смена env **на** `harmonizer.zamkovoi.yoga` как URL (строка в коде).
- Виджеты `/hz` на `zamkovoi.yoga` — **другой** сертификат и vhost.
- Вебхуки Lava на `https://harmonizer.zamkovoi.yoga/api/...` — ожидаемо и нужно.
- Cron и серверные вебхуки на `harmonizer-ten.vercel.app` — от SSL поддомена не зависят.

## Если пользователь настаивает на риске

1. Зафиксировать в ответе: потеря автопродления, ручной тикет в REG.RU или ручные TXT; простой HTTPS для приложения/кабинета/оплаты в РФ.
2. Если цель — «избавиться от второго сертификата»: полный перенос origin = релиз приложения + кабинет + письма + Lava + план TLS; это **не** мгновенная смена DNS.
3. После любых правок DNS/псевдонимов — предложить проверку: `/.well-known/acme-challenge/` отдаёт **nginx** (404 на фиктивный путь), не Vercel (`X-Harmonizer-Proxy`).

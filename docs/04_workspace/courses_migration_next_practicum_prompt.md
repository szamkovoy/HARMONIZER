## 2. Этап А: один проход по учебной последовательности

1. Получи компактную карту **этой одной воронки**: идентификаторы блоков, названия, реальные направленные связи. DOM-порядок и расположение прямоугольников не задают порядок выдачи. Не возвращайся к трём исследованным воронкам пилота и не строй новый общий аудит.
2. Проследи путь выдачи учебных материалов до конца. Нужны: уроки, дополнительные учебные материалы, письма о них, интервалы и завершающее письмо. Блоки групп могут означать доступ/закрытие — выясни назначение, не переноси группы как самостоятельные уроки.
3. **Каждый относящийся к учебному пути блок задержки обязательно открой.** Дождись загрузки настроек именно выбранного блока (сверь его ID). Считай действительные дни/часы/минуты, режим отсчёта, фиксированный день/час. Название «2 дня» не является доказательством: в пилоте оно расходилось с настройками. Сложи последовательные ожидания между выдачами. Не округляй 52 часа до двух дней без решения Сергея: запиши фактическое значение и конкретный вопрос о календарной адаптации.
4. В блоке открытия урока возьми точную ссылку/назначение. В блоке письма — точную рассылку, её ID/название/ссылку. Сначала используй прямое назначение; не ищи письмо повторно, если ссылка уже найдена.
5. Проверки «куплен курс / не куплен», включая проверку **хотя бы одного из двух курсов**, и специальные предложения не переносятся в новую учебную программу. Прочитай условие/назначение настолько, чтобы отличить продажи от обучения и правильно продолжить учебный путь. Не собирай полные тексты чисто рекламных веток. Не исключай бонус лишь потому, что он расположен рядом с предложением. Если после удаления ветки неясна дата следующей учебной выдачи, покажи конкретное расхождение; не угадывай интервал и не прибавляй автоматически ожидания из рекламной ветки.
6. Открой каждую нужную рассылку: тема, текст, абзацы, ссылки и кнопка урока. При поиске: «Рассылки → Все → Название», поле `MailingSearch[title]`; префикс возьми из текущей воронки. `М1_запись:` относится только к пилоту, не ко всем продуктам; М может быть кириллической. Поиск по одному короткому слову не доказывает полноту.
7. Открой урок по назначению или по кнопке письма. Сверь, что это тот материал. Собери **весь учебный текст и все видео в исходном порядке**, включая текст после видео и второе видео, если есть. Не выдумывай заголовков/заданий. Учебные ссылки, изображения и файлы не теряй: сохрани адрес и место в материале; если формат не поддержан, отметь это для внедрения, а не удаляй содержимое. Служебные комментарии GetCourse, формы обратной связи и апгрейда, платёжные формы и социальный низ не являются учебными блоками. Не решай вопрос только по CSS-скрытости: важны назначение и доступное ученику содержание. Спорный учебный блок отметь для Сергея.
8. Vimeo сначала ищи в доступном iframe/разметке урока или его редакторе без сохранения. Проверенные элементы пилота: `.lt-lesson-text .f-text`, `.lt-lesson-video iframe`, `#missionText`; в рассылке — `#Mailing_subject`, `#bodyCell`. Это ориентиры, а не гарантия одинаковой разметки. Если URL уже получен, настройки видео открывать незачем. Если не получен — открой настройки видеоблока и считай URL/ID. Не сохраняй страницу и ничего не загружай на Vimeo.
9. Бонус может находиться не в основном списке уроков: путь **блок → рассылка → кнопка → страница практики** уже проверен. Для видео из каталога Гармонизатора найди существующую практику по Vimeo ID, проверь совпадение и сохрани `practiceId`; не копируй практику. Неоднозначность спроси одним конкретным вопросом. Включение бонусов решается по продукту; для похожих практикумов Сергей ожидает их включение, но это не универсальное правило для всех интенсивов/курсов.
10. Проверяй пропуски/повторы по связям графа. Совпадающий Vimeo ID не означает, что повтор ошибочен: не удаляй учебный повтор без подтверждения. После каждого завершённого материала сохраняй его в рабочий Markdown, чтобы не перечитывать страницы после прерывания.

В GetCourse закрывай настройки без сохранения. Не нажимай отправку, оплату, отписку, запуск процесса. Скриншоты используй при необходимости понять граф/видимость; не делай альбом одинаковых окон, если текст уже читается.

## 3. Что сохраняем и что адаптируем

Письмо сохраняет тему, смысл, авторский текст, абзацы и подпись. Пустая строка — реальный промежуток; один перевод строки не превращай в пустую строку. Учебные видео/тексты урока сохраняй в исходном порядке. Не дописывай собственные объяснения практики.

Вместо кнопки GetCourse, открывающей урок, используй согласованное уведомление: «Урок ждёт вас в Гармонизаторе, на вкладке „День“». Для **письма без нового урока** эту фразу не добавляй. Другие полезные ссылки сохраняй. Устаревшие версии «Автоном/Стандарт/Интенсив», доплаты, сроки и обещания следующих материалов пометь короткой заметкой для авторской правки; не переписывай молча большие фрагменты. Если предлагаешь адаптацию, явно отличай её от извлечённого текста.

Шапка одна на весь практикум: файл Сергея, центрирование, исходные пропорции. В MD достаточно общей ссылки на локальный файл, без копии картинки в каждом разделе. Не подставляй шапку «Месяца здоровья» и его CDN-адрес в другой продукт. На этапе внедрения — существующий email CDN и image-блок редактора с `align=center`.

Не меняй принятые общие правила: одна версия продукта, открытые материалы доступны до общего конца доступа; последний **учебный материал** на «Дне» ещё три дня, затем архив в Профиле; уроки независимы от доставки. Обычное расписание: первый урок/письмо сразу, остальные уроки в местную полночь, письма в 07:00. Правило покупки после 18:00 и сроки доступа/вебинаров бери из действующего spec/плана, не пересогласовывай их без причины. Интервалы конкретного продукта каждый раз подтверждай настройками его воронки.

## 4. Новое решение: завершение письмом без урока

В описанном Сергеем следующем практикуме после пятого основного урока есть **только письмо о завершении**, без нового учебного материала. По его прямому решению: пауза перед этим письмом **три дня после последнего учебного материала вместо пяти дней исходной воронки**. Оно сообщает о завершении показа курса на «Дне»; обычная отправка — в 07:00 соответствующей местной даты. Исходную задержку пять дней и согласованную замену на три укажи рядом, не исправляй GetCourse.

По предварительному описанию: 5 основных + 2 бонусных = **7 материалов, но 8 писем**. Проверь это по источнику. Ожидаемые интервалы материалов: 0, 2, 7, 3, 4, 3, 4 дня; даты D0/D2/D9/D12/D16/D19/D23. Завершающее письмо — D26. Это подсказка для сверки следующего продукта, не шаблон для слепой подстановки всем остальным.

**Не создавай фиктивный восьмой урок**, пустое видео или копию последнего урока ради письма. Завершающее письмо не входит в счётчик полученных уроков, не становится текущим материалом, не продлевает показ на «Дне», архивный доступ или вебинарный пропуск. Сроки привязаны к последнему настоящему учебному материалу. Если в другой воронке в конце действительно есть отдельное видео/урок, сохрани его и применяй правило трёх дней уже после него.

Поддержка уже реализована миграцией `20261118030000_course_completion_email.sql`: `completionEmail` в JSON — отдельное письмо; сроки/счётчик остаются по реальным урокам. В админке у него подпись «без нового урока» и нет кнопки «Урок». После исправления `20261118050000` в ускоренном тесте финальное письмо приходит через две минуты после последнего урока, но карточка на «Дне» остаётся три календарных дня от выдачи последнего настоящего урока. Обычное прохождение сохраняет три календарных дня и 07:00; отправка/ошибка письма не сдвигает границу показа. Для одиночного урока среди дня выбирается первое 07:00 не раньше окончания его трёхдневного показа. Пилот без такого письма сохраняет прежнее тестовое окно три дня.

## 5. Единственный основной результат этапа А

Создай `content/courses/<slug>.review.md`; выбери уникальный slug по названию и проверь отсутствие конфликта. Не трогай `month-health.review.md`. Структура:

- Название, тип, исходная воронка, файл шапки. Кратко: число учебных материалов / писем; подтверждённые интервалы и общая длительность.
- Одна небольшая таблица: № события, тип (урок/бонус/письмо без урока), интервал после чего, накопленный день, название, есть ли письмо.
- Далее линейно каждый материал: **интервал → письмо (тема и полный текст) → урок (название, текст/видео в исходном порядке)**. Формат пилота `## 01. …`, `### Письмо`, `### Урок` удобен для обычных пар; завершающее письмо вынеси отдельным разделом с явной пометкой «Урока нет».
- Для каждого материала достаточно короткой строки источников: ID нужных блоков, ссылка рассылки и урока; для паузы — фактическое значение настройки. Для бонуса — Vimeo ID и найденный practiceId.
- В конце только конкретные вопросы, исключённые рекламные ветки одной строкой и места устаревшего текста для авторской правки. Отметь реально недоступный материал, не заполняй его предположениями.

Для универсального парсера добавь в начало MD техническую шапку (Сергей редактирует содержание ниже, а не JSON):

```markdown
**Код курса:** уникальный-slug
**Название курса:** название практикума
**Тип:** practicum
**Лендинг:** https://…
**Доступ после последнего урока:** N дней
**Показ последнего урока:** 3 дня
**Вебинарный пропуск после последнего урока:** 5 дней
**Шапка писем:** ссылка на файл, при внедрении заменить на HTTPS URL email CDN
**Размер шапки:** ширина×высота
```

Срок доступа `N` Сергей определяет по продукту: не подставляй автоматически 90 дней пилота; неизвестное отметь для авторской проверки, продолжая сбор. У каждого `## 01. …` и далее: `**Когда открывается:** сразу` для первого, `**Когда открывается:** через N дней` для остальных; затем `### Письмо`, `**Тема:** …`, полный текст и `### Урок`, `**Название страницы:** …`, блоки. Видео — отдельной строкой `**Видео:** https://player.vimeo.com/video/ID`; для бонуса на этой же строке можно добавить `practiceId=UUID` подтверждённой практики. Следующий текст после видео остаётся на своём месте. Технические доказательства — в конце материала под зарезервированным `### Источники переноса`, чтобы они не попали в урок/письмо.

Завершение: отдельный `## Завершающее письмо`, строка `**Когда отправляется:** через 3 дня после последнего урока`, затем `### Письмо`, тема/текст; секции `### Урок` у него нет. Исходные пять дней укажи в `### Источники переноса`. Метаданные/ссылки должны быть заполнены перед машинным импортом; локальную картинку сначала размести через email CDN. Парсер выдаёт понятную ошибку при пропущенном интервале/неправильной структуре, не угадывает их за автора.

Отчёт в чате короткий: ссылка на этот файл, что собрано, что осталось уточнить. Не выдавай JSON/SQL или громоздкие графы как главный результат. Сергей читает и правит MD. До его утверждения не импортируй содержание и не запускай тест. История сбора в чате не должна заменять сохранённый документ.

## 6. Этап Б — только после авторского утверждения

Когда Сергей подтвердит готовность текста и попросит внедрить/подготовить тест, работай в том же чате дальше. Перечитай последнюю версию MD, не перезаписывай его авторские правки. Если изменения уже вносились через админку, сохраняй их при импорте.

Используй готовый универсальный путь, без нового программирования:

```bash
node --experimental-strip-types scripts/courses-content.mjs content/courses/<slug>.review.md content/courses/<slug>.json
node --experimental-strip-types scripts/course-import-sql.mjs content/courses/<slug>.json supabase/migrations/<новая_дата>_<slug>_content.sql
```

Первый скрипт не переписывает авторский MD. Второй создаёт только SQL, не применяет его и не запускает письма; откажется перезаписывать уже существующий SQL-файл. До импорта проверь JSON и новую миграцию. Обычная генерация сохраняет существующие уроки/письма; `--replace-emails` / `--replace-lessons` применять только при явном поручении заменить правки в БД. Для удаления существующего материала нужна осознанная отдельная миграция, автоматического удаления нет. Legacy-путь без аргументов оставлен только для пилота; для следующего продукта всегда указывай его файл.

JSON содержит `lessons` с настоящими материалами и при наличии `completionEmail: {subject, markdown}`. Для завершающего письма не добавляй элемент в lessons. Тестовый API `POST /api/admin/courses/tests` принимает `action=prepare,email,courseSlug`; без courseSlug остаётся совместимый default month-health, поэтому для нового продукта обязательно передай его slug. RPC prepare_course_test также принимает slug. Подготовка не запускает курс.
При внедрении: уникальные ID нового продукта, JSON из утверждённого MD, новая миграция импорта, сохранение существующих писем/уроков по умолчанию, общая центрированная шапка. Старые применённые миграции не редактировать. Контроль: количество **реальных уроков и писем отдельно**, интервалы, каждый текст/видео, отсутствие продажных веток, отсутствие изменений чужих курсов. Проверь нужные ошибки и границы, не гоняй полный проект многократно без новых причин.

Используй уже готовые общие экраны и редакторы. Не переделывай дизайн и кэш Дня ради очередного продукта. Новые учебные тексты RU, интерфейс — существующие восемь локалей и темы.

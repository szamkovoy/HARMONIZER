# Brief: Practices Module

Используй этот документ в новом чате, когда задача касается каталога практик, модели данных практик, запуска медитаций/дыхания/асан или сохранения выполненных практик.

## Цель модуля

Сделать единый каталог практик, который объединяет:

- медитации, сейчас основная практика: "Вспышка" / экран Symbols;
- дыхательные практики из модуля Breath;
- асаны из Vimeo, привязанные к одной или нескольким чакрам.

Каталог должен быть удобен для прямого выбора пользователем и пригоден для выбора практики ИИ-ассистентом.

## Уже есть в проекте

- `practices`: глобальный каталог практик.
- `practice_chakras`: связь практики с одной или несколькими чакрами.
- `practice_sessions`: выполненные практики пользователя.
- `user_daily_stats`: агрегат минут/количества практик по дням.
- `user_practice_preferences`: персональная история завершений и предпочтений.
- `modules/breath/core/practices.ts`: список дыхательных практик.
- `app/breath-coherence.tsx`: запуск дыхания через `practiceId`, `durationMs`, `chakra`.
- `app/sacred-symbol-stream.tsx`: текущая точка входа для короткой медитации Symbols.

## Термины

В продукте лучше использовать такие названия:

- `meditation`: медитация;
- `breath`: дыхание / пранаяма;
- `asana` или `yoga`: практики асан.

В БД сейчас `kind` ограничен значениями `breath`, `meditation`, `yoga`. На первом витке не обязательно переименовывать `yoga` в `asana`, можно оставить `yoga` как технический тип, а в UI показывать "Асаны".

## Модель данных

Текущая таблица `practices` уже близка к нужной:

- `slug`: стабильный ключ;
- `kind`: `breath | meditation | yoga`;
- `title`: `{ ru, en }`;
- `description`: `{ ru, en }`;
- `default_duration_sec`, `min_duration_sec`, `max_duration_sec`;
- `params`: расширяемый JSON;
- `video_provider`, `video_url`, `video_external_id`;
- `rating`: можно использовать как качество;
- `is_active`, `version`.

На первом витке желательно добавить или договориться о хранении:

- `recorded_at` для Vimeo-асан, nullable;
- `source` или `params.source`, например `vimeo_import`;
- `instruction_video_external_id` или `params.instruction_video`, если позже появятся отдельные видео-инструкции;
- `duration_policy` можно хранить в `params`: `fixed` для асан, `user_selectable` для дыхания/медитации.

Если нужен минимальный путь без миграции:

- quality хранить в `rating`;
- дата записи: `params.recorded_at`;
- длительность Vimeo: `default_duration_sec`;
- Vimeo id: `video_provider='vimeo'`, `video_external_id='<id>'`;
- несколько чакр: `practice_chakras`.

## Первый виток реализации

### Шаг 1. Клиентский контракт

Создать модуль `modules/practices`:

- `core/types.ts`: `PracticeKind`, `PracticeSummary`, `PracticeLaunchParams`.
- `core/catalog.ts` или `api/practicesClient.ts`: загрузка/сбор каталога.
- `ui/PracticeCatalogScreen.tsx`: экран каталога.
- `ui/PracticeCard.tsx`: карточка практики.
- `readme.md`: контракт модуля.

На первом витке допустимо собрать каталог смешанно:

- дыхание из `BREATH_PRACTICES`;
- медитация как статическая запись;
- асаны из Supabase, если данные уже импортированы, иначе пустая группа с заглушкой.

### Шаг 2. Экран каталога

Экран должен показывать группы:

- "Медитации";
- "Дыхание";
- "Асаны".

При клике на группу открывается список практик. В карточке достаточно:

- название;
- тип;
- длительность: фиксированная или выбираемая;
- чакра: фиксированная или выбираемая;
- quality, если есть;
- кнопка запуска.

### Шаг 3. Запуск практик

Медитация:

- запускать существующий `app/sacred-symbol-stream.tsx`;
- в будущем передавать цвет/чакру/длительность, если экран будет поддерживать параметры.

Дыхание:

- запускать `app/breath-coherence.tsx`;
- передавать `practiceId`, `durationMs`, `chakra`.

Асаны:

- если player еще не готов, сделать экран-заглушку `app/asana-practice.tsx`;
- он должен принимать `practiceId` и показывать metadata;
- Vimeo player можно вынести на следующий виток.

## Сохранение результатов

На первом витке не обязательно сохранять все практики. Но контракт должен предусматривать запись в `practice_sessions`:

- `user_id`;
- `practice_id`;
- `practice_slug`;
- `started_at`, `ended_at`;
- `self_rating`: `-1 | 0 | 1`;
- `completion_pct`;
- `metrics`: JSON для Breath/биометрии;
- `chakra_focus_ids`;
- `context`: источник запуска (`catalog`, `assistant`, `debug`), выбранная длительность, выбранная чакра.

Для Breath итог уже есть как `BreathPracticeOutcome`. На втором витке его можно сохранять в `metrics`.

## Алгоритм выбора для ассистента

На первом витке достаточно подготовить данные так, чтобы будущий selector мог:

- фильтровать по `kind`;
- фильтровать по чакре через `practice_chakras`;
- учитывать длительность;
- сортировать по `rating desc`;
- учитывать `recorded_at asc` внутри одинакового качества;
- исключать recent stack пользователя.

Важно: `quality/rating` и `recorded_at` nullable. Отсутствие этих значений не должно ломать сортировку.

## Вопросы перед реализацией

- Нужно ли прямо сейчас добавлять миграцию для `recorded_at`, или пока хранить дату в `params.recorded_at`?
- Как назвать тип асан в пользовательском интерфейсе: "Асаны", "Йога", "Практики асан"?
- Для "Вспышки" длительность сейчас фиксированная или уже на первом витке делаем выбор длительности?
- Нужен ли выбор чакры перед прямым запуском из каталога, или только при рекомендации ассистента?

## Критерии приемки первого витка

- Есть экран каталога практик.
- Дыхательные практики отображаются по текущему списку Breath.
- "Вспышка" отображается в разделе медитаций.
- Можно запустить дыхательную практику из каталога с выбранными/дефолтными параметрами.
- Структура кода готова к добавлению Vimeo-асан без переписывания UI.

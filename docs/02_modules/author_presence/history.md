## Decision Log

- **2026-07-09 (17):** Исправлена локализация user-generated контента сторис и публикаций на клиенте. Причина: `storiesClient` брал только `caption.text` (RU) и игнорировал `caption.translations`; `postsClient` и RPC `get_posts_feed` отдавали только RU `title`/`body`/`cover_url`. Исправление: общий хелпер `modules/i18n/pickLocalizedContent.ts` (`pickLocalizedText`, `pickLocalizedUrl`); `StoryViewerModal` вызывает `resolveStoryCaption(caption, locale)`; публикации — `resolvePostContent` в feed/banner/экране поста; миграция `20260709110000_posts_feed_i18n.sql` расширяет `get_posts_feed` полями `title_i18n`/`body_i18n`/`cover_url_i18n`. Fallback — RU source, если перевода нет.

- **2026-07-09 (16):** Устранён visual back-jump на старте video-stories. Причина: poster-first слой показывал `cover_url`, а cover для уже обработанных роликов извлекался не из нулевого кадра, а из чуть более позднего момента, поэтому при старте MP4 с `t=0` возникал эффект микродвижения «назад». Исправление двойное. (1) В `StoryViewerModal` poster теперь показывается только для cold-start video; если ближайший ролик уже был заранее прогрет отдельным `expo-video` player, viewer сразу скрывает `cover_url` и показывает только сам `VideoView`. (2) Server-side pipeline больше не делает seek на `0.2s` перед генерацией `cover.jpg`: poster берётся с самого начала ролика, чтобы будущие uploads были синхронны со стартом MP4. Код: `modules/stories/ui/StoryViewerModal.tsx`, `_legacy_web/app/api/admin/stories/mediaPipeline.ts`.

- **2026-07-09 (15):** Stories video-playback доведён до poster-first / prebuffer схемы без «мёртвого первого кадра». `StoryViewerModal` переведён с `expo-av` `Video` на `expo-video` (`VideoView` + `useVideoPlayer`): fullscreen `cover_url` теперь всегда лежит под видеослоем, сам `VideoView` становится видимым только после `onFirstFrameRender`, поэтому переход photo → video больше не показывает долгий статичный кадр поверх чёрного/шторки. Для ближайшего следующего direct-video viewer держит отдельный заранее загретый player (двухслотовая схема current/next), а source загружается с `useCaching` и ускоренным стартовым буфером (`preferredForwardBufferDuration=2`, `waitsToMinimizeStalling=false`, `timeUpdate` каждые 100 мс для точного прогресса). Код: `package.json`, `modules/stories/ui/StoryViewerModal.tsx`, `modules/stories/core/storiesClient.ts`.

- **2026-07-09 (14):** Починен server-side video process для stories и одновременно подтянуты самые эффективные рекомендации из видео-PDF. Причина ошибки в админке: runtime `POST /api/admin/stories/process` иногда получал от bundled `ffprobe-static` неверный путь (`/ROOT/node_modules/...`, без надёжной привязки к реальному package dir), из-за чего `spawn ... ffprobe ENOENT` падал ещё до обработки файла. Исправление: `mediaPipeline.ts` теперь вычисляет абсолютные пути к `ffprobe` и `ffmpeg` от `package.json` пакета через `createRequire(import.meta.url)` + `existsSync/accessSync(X_OK)` fallback, а не слепо доверяет экспортам пакетов. Попутно video pipeline подтянут к рекомендациям PDF: MP4 `H.264 High` + `AAC 128k`, `30 fps`, `1080x1920` crop вместо preserve-aspect-ratio shrink, `-movflags +faststart`, poster `cover_url` тоже `1080x1920`. Это улучшает и upload reliability, и perceived startup в viewer, потому что poster теперь совпадает с fullscreen-композицией сторис. Код: `_legacy_web/app/api/admin/stories/mediaPipeline.ts`.

- **2026-07-09 (13):** Самый перспективный недореализованный пункт из PDF внедрён буквально: stories image-layer переведён на `expo-image`. `storyMediaPreload.ts` больше не использует `react-native` `Image.prefetch`; вместо этого preload = `expo-image` `Image.prefetch(..., "memory-disk")` + `Image.loadAsync()` для нативного cache+decode. Из-за этого удалён промежуточный hidden-warmer `StoryImageWarmer`: готовность кадра теперь определяется по завершению native preload/decode, а не через невидимый `1x1 <Image />`. `StoriesRing.openViewer()` больше не открывает modal, пока не завершится preload/decode первого fullscreen-кадра, а сами fullscreen image-слои во viewer тоже переведены на `expo-image` (`cachePolicy="memory-disk"`, `transition={0}`). Прогресс по-прежнему остаётся синхронизирован с `displayIndex`. Код: `package.json`, `modules/stories/core/storyMediaPreload.ts`, `modules/stories/ui/{StoriesRing,StoryViewerModal}.tsx`.

- **2026-07-09 (12):** Откачен неудачный fullscreen blur-up с `thumbnail_url`: квадратная ring-thumbnail не соответствует пропорциям полноэкранной сторис и визуально дёргала экран сильнее, чем чёрный фон. Вместо этого viewer переведён на более буквальное следование PDF-исследованию: `StoriesRing` заранее скрыто декодирует окно full-кадров через `StoryImageWarmer`, а `openViewer()` ждёт `waitForStoryMediaPainted(firstFullUri)` перед показом modal. Во viewer скрыто декодируется neighborhood `2 назад + 3 вперёд`, а переход на следующую сторис происходит только после готовности её fullscreen URI; прогресс остаётся привязанным к `displayIndex` и больше не опережает фотографию. `storyPlaceholderUri` для image-stories больше не возвращает square thumb, чтобы fullscreen-слой не мог снова использовать неподходящий preview. Код: `modules/stories/core/{storyMediaPreload,storiesClient}.ts`, `modules/stories/ui/{StoryImageWarmer,StoriesRing,StoryViewerModal}.tsx`.

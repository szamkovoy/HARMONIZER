## 1. Назначение

Модуль **practices** объединяет каталог практик в приложении (медитация, дыхание, асаны из БД), единый способ **запуска** по маршрутам Expo Router и **запись сессий** в Supabase для статистики и контекста ассистента. Рантайм-дыхание и синхронизация звука с фазами вынесены в **`modules/breath/`** (внутренний движок подсценария дыхания; в `MAP.md` не выделяется отдельным модулем).

## 2. Публичный контракт

### Пакет `modules/practices` (`index.ts`)

- **`getPracticeCatalog(locale): PracticeCatalog`** (синхронный, канонический источник)  
  Собирает каталог мгновенно: статические медитации «Вспышка» и **«Спокойствие»** (`slug: calm`, без чакр, `counts_in_reports: false`), дыхательные практики из `BREATH_PRACTICES` (`modules/breath/core/practices.ts`), асаны из **build-time snapshot** `modules/practices/data/yoga-catalog.snapshot.json` (коммитится в репо; генерируется `scripts/generate-practice-catalog-snapshot.mjs` → `npm run update-practice-catalog-snapshot`, который prepend-нут во все build-скрипты). Snapshot — сырые строки `practices` с `kind = 'yoga'`, `is_active = true` и embedded `practice_chakras` (тот же select, что раньше делал `loadYogaPractices` к Supabase); runtime-локализация через `resolveYogaPracticeTitle` остаётся без изменений. Приложение **не делает** сетевого запроса к Supabase при открытии каталога — счётчики и список асан известны в бинаре сразу. Если количество практик изменится в БД, новый snapshot попадает в приложение только со следующим билдом (снимок обновляется build-скриптом при наличии сети; если сети нет — остаётся закоммиченный). `getYogaCatalogSnapshot(locale)` — sync-обёртка только над йогой, memo-кэшированная per locale. UI-строки каталога — **`getPracticeCatalogStrings(locale)`** (`modules/practices/i18n/practices.ts`, `PracticeLocale = AppContentLocale`).

  **`loadPracticeCatalog(options?, deps?): Promise<PracticeCatalog>`** и **`loadYogaPractices(locale?): Promise<PracticeSummary[]>`** сохранены как async-обёртки для обратной совместимости и тестов (deps-инъекция `loadYogaPractices`); мгновенно резолвятся из snapshot, не трогают сеть. Опции `onLateYogaPractices` / `initialYoga` игнорируются (йога мгновенная) — оставлены только для совместимости со старыми вызовами.

- **`filterPractices(practices, filters): PracticeSummary[]`** / **`sortPracticesForCatalog(practices): PracticeSummary[]`**  
  Фильтр по чакре и «корзине» длительности; сортировка через `@shared/selector`.

- **`practiceDurationDistance`**, **`practiceQuality`**, **`practiceRecordedAtMs`**, **`recentStackLimitForKind`**, **`selectPracticeCandidate`**, **`sortPracticeCandidatesForCatalog`**, **`sortPracticeCandidatesForRecommendation`**  
  Реэкспорт из `@shared/selector` для каталога и для серверного выбора практики (см. `practiceSelection.ts`).

- **Типы:** `PracticeCatalog`, `PracticeCatalogFilters`, `PracticeDurationBucket`, `PracticeDurationPolicy`, `PracticeKind`, `PracticeLaunchParams`, `PracticeSummary`, `PracticeVideoMetadata`, `PracticeSelectorCandidate`, и т.д.; **`PracticeRecommendation`**, **`PracticeRecommendationLaunch`** из `@shared/recommendation`.

- **`PracticeCatalogScreen`**  
  UI вкладки «Практики»: каталог собирается **синхронно** через `getPracticeCatalog(locale)` на mount — спиннер «Собираем каталог...» и состояние `loading` убраны; счётчики групп (медитации/дыхание/асаны) и список асан видны мгновенно из зашитого в бинарь snapshot. Сетевой запрос к Supabase при открытии вкладки больше не выполняется. При смене локали каталог пересобирается (titles локализуются через `resolveYogaPracticeTitle`). Prefetch миниатюр Vimeo пропускает карточки, у которых уже есть сохранённый `video_thumbnail` из snapshot.

- **`launchPractice(launch, options?): boolean`**  
  Навигация: поддерживает `PracticeLaunchParams` (каталог) и `PracticeRecommendationLaunch` (объект с `route` + `params` от ассистента). Добавляет `launchSource` в query при необходимости. Возвращает `false`, если нет `launch.route`.

- **`assistantPracticeOverlayDismiss.ts`** — `scheduleAssistantOverlayDismiss(callback)`, `signalAssistantPracticeScreenMounted()`, `clearAssistantOverlayDismiss()`; module-level координация закрытия full-screen overlay коммуникатора после mount экрана практики и min-delay **200 ms** (fallback timeout **2500 ms**).

- **`AssistantPracticeHandoffCover.tsx`** — непрозрачный full-screen cover (`ActivityIndicator` на `screenBg`); Home/Day modal показывает его вместо чата между `onPracticeLaunchStart` и dismiss overlay, чтобы под full-screen Modal не мелькала вкладка.

- **`useAssistantPracticeOverlayDismiss(launchSource)`** — hook для route-обёрток (`breath-coherence`, `sacred-symbol-stream`, `asana-practice`): при `launchSource=assistant` на focus экрана (`useFocusEffect`) после `InteractionManager.runAfterInteractions` + двойного `requestAnimationFrame` вызывает `signalAssistantPracticeScreenMounted()`.

- **`PracticeCard`** (`modules/practices/ui/PracticeCard.tsx`)  
  Единый UI-компонент карточки практики для каталога и коммуникатора. Поддерживает override `duration` и, для практик без жёсткой привязки к видео, override `chakra`; локализация и кнопка запуска одинаковы в обоих входах. Подписи длительности (`от`/`from`, `мин`/`min`) берутся из **`getPracticeCatalogStrings`** (`durationFromPrefix`, `durationMinUnit`), а не из сравнения `locale === "en"`. Значение `overrideDurationMinutes` **клипится** к списку допустимых минут (`**assistantSelectableDurations.ts**`, синхронно с сервером для дыхания 5–20 и медитации 1–5); при клипе — `console.log` с тегом **`[PRACTICE_CARD_MISMATCH]`** (поля в духе серверного JSON плюс **`source: "practice_card_client_sync"`**, `conversationId` обычно `null`). После ручного выбора минут карточка не синхронизирует состояние обратно с catalog/default props, пока не сменилась сама `practice.id`, поэтому пользовательская длительность медитации/дыхания не сбрасывается перед запуском. Дефолт чакры для meditation/breath берётся из `primaryChakra` / `chakraIds`, если поверхность передала дневной фокус. Для **breath** карточка добавляет ComboBox **темпа** (`tempoLabel` = «Темп:» / «Tempo:»): первый пункт списка — невыбираемый header (`ComboBoxOption.header`); линейные/квадрат — `2…12` (дефолт linear **6**, square **4**); `triangle-up` / `triangle-down` — фиксированные тройки (`4:4:4` по умолчанию, списки в `modules/breath/core/breath-tempo.ts`). Значение уходит в launch как **`tempo`**. Сохранение в SecureStore (`harmonizer.breath.tempo.preferences.v1`, отдельно на каждый из 7 `BreathPracticeId`) происходит только после реального старта практики (`phase === "running"`) или смены темпа на экране практики — правка на карточке без «Начать» дефолт не меняет. Если в оверлее выбрали >12, в prefs/карточку пишется ближайшее из списка (max **12**). Для **breath** и **meditation** — ComboBox **«Звук»** (`soundLabel` / `soundBeds.*`): `neuro-sync` (default) или один из 8 nature beds → **`soundBed`**. Yoga без этих селекторов. Для дыхания дополнительно `sensorMode = "fingerCamera" | "ble" | "none"`; BLE подставляет remembered device из wearable preferences; legacy `usePulseSensor` для старых deep-link/assistant payload. BLE без ремня: CTA «Найти пульсометр» → `WearablePickerDialog`; на Android «Подключить» ждёт live HR. Remembered-ремень перепроверяется live-probe при foreground. Селекторы — **`ComboBoxRow`**; `useFocusEffect` сворачивает открытые селекторы и обновляет темп из prefs. Для **`kind = "breath"`** — «?» (`SurfaceCardTitleRow` + `SurfaceHelpModal`, `breathHelp*`). Для **`kind = "meditation"`** — `meditationFlashHelp*` / `meditationCalmHelp*`.

### Утилита `modules/practices/core/assistantSelectableDurations.ts`

- **Асаны: две кнопки в карточке.** Для `kind = "yoga"` карточка **всегда** показывает две кнопки — **«Открыть на телефоне»** (primary, `onLaunch` → `/asana-practice`) и **«Открыть на ТВ»** (secondary, `onRemotePlay`), независимо от того, подключён ТВ или нет, и независимо от контекста (каталог `PracticeCatalogScreen` или коммуникатор `Communicator`). Прежняя панель «TV connected · code» + «Сменить ТВ» над фильтрами каталога удалена. ТВ-путь инкапсулирован в хуке **`useAsanaRemotePlayLauncher(strings)`** (`modules/practices/ui/useAsanaRemotePlayLauncher.ts`): `vimeoId` валидируется до навигации (при отсутствии — алерт «Видео недоступно»); если `useRemotePlay().connected` false → `router.push({ pathname: "/connect-tv", params: { vimeoId, title, durationSec, audiotrack } })`; если подключён → `remotePlay.playVimeo(vimeoId, vimeoAudiotrackForLocale(locale))` и навигация на `/tv-remote` с `{ title, durationSec }`. Каталог передаёт `onRemotePlay` с access-tier проверками по kind (`meditations` / `breath_practices` / `asana_practices`) и per-practice busy-флагом; коммуникатор — без tier-проверок (практика уже прошла через сервер). `remotePlayConnected`-пропс `PracticeCard` убран.

- **Каталог browsable для всех уровней (2026-07-15).** Каталог (медитации/дыхание/асаны) виден и browsable для **всех** тарифов — пользователь может переключать группы и листать карточки. Гейт (`AccountGateDialog`) срабатывает только при попытке запустить практику: тап по «Начать практику» (медитация/дыхание) или «Открыть на телефоне»/«Открыть на ТВ» (асаны). Ключ гейта выбирается по `practice.kind`: `meditations` / `breath_practices` / `asana_practices`. Раньше гейт срабатывал уже при тапе по группе (через единый ключ `practice_catalog`); это исправлено — `catalogAllowed`/`locked` проверки из onPress групп удалены, `masterOnly`-подпись на карточке группы заменена на счётчик.
- **Вкладка «День» — тот же гейт запуска (2026-07-21).** Выбор/отмена pending-практики на `app/(tabs)/day.tsx` доступны с `day_planning` (oracle+), но «Начать практику» на pending `PracticeCard` проходит через `tryLaunchDayPractice` → тот же `AccountGateDialog` по kind, что и каталог. Без Master практика не стартует (`launchSource: "day"` только после `canUseFeature`).

- Канонический клиентский модуль: **`selectableDurationMinutesForPracticeCard`**, **`clipDurationMinutesToSelectableMinutes`**, константа **`PRACTICE_CARD_DURATION_MISMATCH_THRESHOLD_MIN`** (2) для логов расхождения маркера с историей в `resolvePracticePublic`.
- Для Vercel-only deploy (`_legacy_web`): копия в **`_legacy_web/shared_core/assistantSelectableDurations.ts`** (импорт **`@shared/assistantSelectableDurations`** из **`route.ts`**); содержимое должно оставаться синхронным с клиентским файлом (как у **`@shared/selector`**).

### Сервис `services/practiceSessions.ts`

- **`recordPracticeSession(input): Promise<string | null>`**  
  Вставка в `practice_sessions`. Поля, которыми пользуются экраны: `user_id`, `practice_id` (опционально), `practice_slug`, `practice_version`, `started_at`, `ended_at`, `self_rating`, `completion_pct`, `metrics` (jsonb), `chakra_focus_ids`, `context` (jsonb).

- **`loadDailyPracticeStats(userId, limit?): Promise<DailyPracticeStat[]>`**  
  Чтение `user_daily_stats`: `user_id`, `local_date`, `total_practice_seconds`, `practice_count`, `chakras_touched`, `updated_at` (последние `limit` строк по дате desc).
  Дополнительно вкладка «День» через `services/dayHealthContext.ts` читает последние строки `user_daily_stats`, чтобы перед summary-веткой дать ассистенту compact-сравнение йоги за подытоживаемый день с обычной практикой пользователя. Текущее baseline-сравнение берётся по 7 последним дням как реальное дневное среднее (нулевые дни тоже учитываются); если исторической базы нет, server prompt использует мягкий ориентир достаточности около 30 минут практики в день.

- **`loadDailyPracticeStatsInRange(userId, fromLocalDate, throughLocalDate): Promise<DailyPracticeStat[]>`**  
  Тот же select по `user_daily_stats` за **включительный** календарный диапазон локальных дат (ascending). Используется вкладкой профиля для «Статистики практик» (7/30/90 локальных дней по `users.tz`).

- **`selfRatingFromMood(mood)`** — маппинг настроения на `self_rating`. Сохранён для совместимости; ни экран результатов дыхательной практики, ни медитация «Вспышка» больше не показывают mood-picker (см. history 2026-07-04 (16) и 2026-07-05 (17)) и записывают сессию с `self_rating = null` — дыхание при появлении результатов, медитация в момент `elapsed >= durationMs`.

### Роуты приложения (контракт query-параметров)

- **`app/breath-coherence.tsx`** → `CoherenceBreathScreen`: `practiceId` (`BreathPracticeId`), `durationMs`, `chakra` (1–7), **`soundBed`** (omit/`parseSoundBedId` → `neuro-sync`), **`tempo`** (`resolveTempoKey` — single или `a:b:c` для треугольников), `launchSource`, launch-контракт `sensorMode`, `deviceId`, `deviceName`, `provider`, `capabilityTier`, `connectionHint`, `autoReconnect`; `usePulseSensor` остаётся backward-compatible флагом (`"false"` трактуется как `sensorMode = "none"`). Оверлей темпа: для non-triangle — одно число и стрелки ± (min 1, max 60); для треугольников — тройка `a : b : c` и шаг по пресет-списку (на краях стрелка скрыта). `buildShapeForTempo` задаёт удары на фазу (у треугольников грани могут иметь разную длительность).

- **`app/sacred-symbol-stream.tsx`** → `SacredSymbolStreamScreen`: `durationMs`, `chakra`, **`soundBed`** (default `neuro-sync`), `launchSource`. Параметр **`practiceId` из каталога не читается** для «Вспышки». **Keep-awake** (`PracticeKeepAwake`) на всё время экрана до finish — экран не гаснет.

- **`app/calm-practice.tsx`** → `CalmPracticeScreen`: `durationMs`, `soundBed` (default `neuro-sync`). Полноэкранный образ из `CALM_BED_IMAGES`, без чакры, без `recordPracticeSession`. Confirm stop — только title + кнопки. Audio: `staysActiveInBackground` (экран может гаснуть) + **`lockScreen: { title: catalogStrings.meditationCalmTitle, artwork: imageSource }`** — локализованное название «Спокойствие» и та же обложка, что на экране практики, показываются в OS media-notification / lock-screen карточке (как у YouTube). На Android именно `setActiveForLockScreen` (foreground service `AudioControlsService`, тип `mediaPlayback`) держит аудио живым часами в Doze — без него ОС душит звук через ~3 минуты. Interruption handling: `useMandalaSoundInterruption()` — пока ОС приостановила аудио (звонок / чужое приложение), elapsed-таймер палятся (сдвиг `sessionStartedAtRef` вперёд на длительность паузы при resume), и `finishPractice` не срабатывает во время прерывания — практика звучит ровно N мин реального аудио. При возврате в app `MandalaSoundProvider` вызывает `resume()` (повторный запрос фокуса). См. `audio/history.md` (нативный патч `expo-audio` для sustained focus). Ассистент эту практику не предлагает (серверный `STATIC_MEDITATION` остаётся только «Вспышка»). UI медитации унифицирован с дыхательной практикой через общий шелл **`modules/ui/PracticeOverlayPanel.tsx`** (slide-up/down, themed card, заголовок, полоса прогресса, слот `controls`); экран полностью чёрный + canvas, без верхнего заголовка/описания. Оверлей стартует **скрытым** (`initialVisible: false`) и автоматически всплывает через **5000 мс** после открытия экрана (`OVERLAY_HINT_DELAY_MS`), затем уезжает вниз через те же **4000 мс** авто-скрытия (`OVERLAY_AUTOHIDE_MS`), что и у дыхания (`useImmersiveOverlayAutohide`); тап по экрану toggles оверлей так же. Карточка панели полупрозрачная (`PANEL_CARD_BACKGROUND = "rgba(20,22,28,0.72)"`, общий шелл — единая полу-прозрачность для дыхания и медитации), slide 320 мс с bezier-easing. Сверху-справа `FloatingCloseButton` пока панель видна, зафиксирован на `top: 54, right: 18` — та же позиция, что у дыхательной практики. По тапу всплывает панель (title "Вспышка" + кнопка «Завершить» в слоте `controls`). Mood/rating-диалог удалён — **отметка завершения** (`recordPracticeSession`, `completionPct: 100`, `selfRating: null`) ставится в elapsed-tick эффекте в момент `elapsed >= durationMs` (до закрытия окна), не в окне оценки. **Окно подтверждения остановки** использует те же строки, что и дыхательная практика (`getCoherenceBreathStrings(locale)` — title/message/continue/finish), с единым текстом сообщения «Практика будет остановлена, а результаты по прошедшему отрезку не будут засчитаны.» (RU + 7 локалей). По завершению экран плавно затемняется в чёрное (600 мс) и возвращает пользователя: при `launchSource = "assistant" | "day"` → `/day`, иначе `router.back()` (каталог/карточка или вкладка «День»).

- **`app/asana-practice.tsx`**: `practiceId` (UUID строки практики), опционально `durationMs`, `chakra`, `launchSource`, **`vimeoId`** (из каталога при launch — чтобы не мигать «нет Vimeo ID» пока грузятся metadata). **Keep-awake** пока открыт плеер. Экран асаны — **только телефонный плеер** (выбор «телефон/ТВ» перенесён на уровень карточки практики, см. `PracticeCard`): сверху `ScreenHeader` (только название, без подзаголовка), под ним встроенный Vimeo-плеер на `react-native-webview` **без** RN-оверлея/спиннера поверх (QA: оверлей залипал и блокировал старт). Bootstrap (`vimeoEmbedHtml` / `web_cabinet/asana-embed.html`): `ready`/`loaded` после `player.ready()`, выбор quality **не** блокирует play (раньше ждал qualities → дольше чёрный кадр). **iOS** — `vimeoEmbedHtml`+`baseUrl: VIMEO_EMBED_BASE_URL`. **Android** — `vimeoPhoneEmbedPageUrl` → `https://zamkovoi.yoga/asana-embed.html` (деплой с `web_cabinet/`); при HTTP ≥400 — fallback html+`originWhitelist: ["*"]`. `baseUrl` / hosted page дают `Referer: https://zamkovoi.yoga/` для domain-privacy Vimeo. URL `?audiotrack=<slug>` без других query. Аудиодорожка — `vimeoAudiotrackForLocale`: `ru → "ru"`, иначе `"en"`. ТВ-путь — через карточку (`useAsanaRemotePlayLauncher`). Под плеером — **«Завершить практику»**; ✕/кнопка при незавершённом — `PracticeStopConfirmDialog` (`getAsanaScreenStrings.stopConfirm*`, досрочный выход не в статистику). Зачёт: Vimeo `ended` **или** watched ≥ `targetDuration − 10s` (`asanaSessionCredit.ts`). `exitAfterPractice`: `assistant|day` → `/day`, иначе `back`.

  **ТВ-страница `https://zamkovoi.yoga/tv`** (WordPress Custom HTML, `docs/remote-play/wordpress-snippet.html`) определяет **язык интерфейса по query из приложения** (компактный `?pt`, также `?l=` / `?lang=` / `?locale=`), иначе **`ru`** для голого `/tv`. Язык браузера ТВ **не** используется (Smart TV часто ru, пока в приложении выбран pt). Ссылки строит **`tvPageUrl(locale)`** (`https://zamkovoi.yoga/tv?pt`). На пульте: название практики — `dialogTitle` (жирный обычный), URL — `screenTitle` (крупно), под ним `openOnTvCaption`. Локализация — инлайн-таблица `STRINGS` для 8 локалей; eyebrow `${appName} ${remotePlay}`. Колонка `tv_sessions.locale` удалена; **`audiotrack`** пишется приложением (`vimeoAudiotrackForLocale`: ru→`ru`, иначе→`en`) и задаёт дорожку iframe; при `null` сниппет берёт дорожку из UI-локали URL. Autoplay стартует **muted** + overlay «включить звук»; жест на странице разблокирует звук (sessionStorage).

### Дыхательный движок `modules/breath` (исполнение, не barrel `practices`)

- **`CoherenceBreathScreen`** (пропсы см. компонент): мандала + звук + сенсорный режим `fingerCamera | ble | none`; BLE-сценарий может стартовать как с уже remembered chest strap, так и с девайса, только что выбранного в модальном поиске из `PracticeCard`. Для BLE экран больше не прыгает прямо в живую практику с первым неизбежным `0 bpm`: если выбран BLE-датчик, старт проходит через activation/preparation gate (spinner + «Отменить» на iOS/Android; hang watchdog → диалог) и переводит экран в `running` только после `guidedOnly/fullMetrics`. В каталоге `PracticeCard`: last BLE unavailable → default `preferredSensorMode: "none"` («без пульсометра»); старт с мёртвым BLE блокируется alert’ом. Если в первые секунды выбранный ремень не выходит в ready-state или отваливается, поверх running-экрана открывается тот же общий `WearablePickerDialog`, чтобы пользователь мог выбрать другой датчик без дублирования UI/логики поиска. Если конкретный `deviceId` ещё не передан, экран всё равно умеет предложить выбор устройства тем же диалогом и по завершении так же пишет **`metrics`** из исхода дыхания (`outcomeToCommunicatorPayload`) в `practice_sessions`. Для `fingerCamera` production-flow теперь работает в guidance-only режиме: камера используется только для live pulse/BPM, а running/results copy прямо объясняет, что advanced HRV/coherence/RSA в camera-mode отключены. При длинной потере живого сигнала практика может временно перейти на emulated pulse, засеянный последним стабильным BPM: seed строится из `pipeline.getLastStableRrMs()` (когерентный baseline, обновляется только на low-jitter окне), а при его отсутствии — из безопасного ритма покоя 65 bpm с clamp в физиологический диапазон 50–90, чтобы шумовой outliers не уводил синтетику. Тот же когерентный baseline теперь используется и для стартового seed-а planner-а на переходе в `running`, и для guidance-значения во время camera-hold (пока не пришёл первый живой beat) — это убирает стартовый «пол» графика guidance, когда шумовой `snapshot.pulseRateBpm` с warmup (~55 bpm при реальном ~80) seeding-овал planner и лог. Сам `lastStableRrMs` сохраняется через finger-off hard-reset (`softReset()` на долгом отсутствии пальца больше его не обнуляет), поэтому emulated после длинного отрыва пальца ведёт дыхание на реальном ритме пользователя, а не на дефолте 65; обнуляется только на session-start `softReset`. для камеры real sensor остаётся на фоне на той же capture-session и периодически делает recovery-probe окна, а для BLE runtime продолжает держать соединение/reconnect, но временно не публикует свои beats поверх эмуляции. Camera long-loss теперь детектируется по возрасту последнего свежего beat, поэтому fallback/recovery не зависят только от того, как контакт выглядит в текущем snapshot; как только hard loss уже подтверждён, camera guidance-only сразу уходит в `emulated`, не ожидая ещё один полный timeout. Короткие camera-hold окна (recent `holding`/`tracking`, non-emulated, non-reacquiring, beat-age ≤ 5 s) теперь считаются ещё живым measured pulse для runtime/results — это и есть явная продуктовая интерполяция короткого finger-lift, чтобы ~3-секундные отрывы не превращались сразу в широкую серую дыру. На source-level короткий beat-gap тоже больше не объявляется «полной новой реакквизицией», если по последнему стабильному RR это всё ещё лишь несколько пропущенных ударов: практика сохраняет пре-gap BPM-контекст и возвращается к real pulse без лишней второй полосы `holding + 0 bpm` уже после возврата пальца. Camera recovery-probe теперь считается успешным только если **новый живой beat** появился уже после старта текущего probe-window; stale pre-probe/emulated snapshot больше не может ложноположительно вернуть практику в live-режим. Если optical path снова явно видит палец/живой поток, probe может оставаться активным дольше короткого стартового окна, чтобы реально восстановить beats, а не сбрасываться серией слепых 2.5-секундных burst-ов. Пока `pulseSource=emulated`, runtime snapshot для UI и `pulseLog` не показывают synthetic `tracking`/`hasFreshBeat` как будто это реальный optical lock: guidance BPM может продолжать вести дыхание, но статус измерения остаётся `searching` до реального возврата камеры. Как только камера снова даёт валидный `tracking`-пульс или BLE снова приносит свежий HR/RR, практика автоматически и без ручного перезапуска возвращается на живой сигнал. Если OS всё же уводит BLE-практику в `background`/sleep, возврат больше не должен auto-abort только потому, что optical snapshot пуст: wearable runtime восстанавливается по собственным RR/heart-rate признакам. Advanced метрики остаются только у BLE-датчиков, которые реально передают RR (`capabilityTier = fullMetrics`); `guidedOnly`-ремни продолжают вести ритм дыхания без финальной HRV-аналитики, но their off-body packets are no longer treated as valid live biometrics when `sensorContactDetected = false`. Прежний hybrid start/end measurement path для обычной camera-практики больше не активируется. Results-stage теперь показывает не только числовую таблицу, но и time-series charts: camera-mode получает pulse chart, а если guidance и live measurement расходятся — отдельные графики `Pulse (measured)` и `Pulse (guidance)`; BLE-results могут показать pulse + coherence + RSA + RMSSD + stress even when final aggregate metrics had to be withheld, because charts reflect the real captured segment while the summary row and interpretation CTA remain gated by final biometric reliability. Pulse results apply the same stable-recovery invariant as runtime: non-live windows separated by less than 8 seconds of stable recovery are rendered as one continuous gap, guidance holds the last accepted live BPM through camera hold windows, and short recovery spike-runs in pulse charts are removed without affecting HRV/RSA/coherence calculations. All result charts use the same `0…practiceTotalMs` time domain: sparse BLE metric series no longer compress the x-axis to the last point or draw fake horizontal left-edge plateaus before the first real metric sample, and coverage-only leading/trailing coherence zeros are trimmed from display so the chart does not pretend that the user had a real `0%` signal for those seconds. Кнопка `Интерпретация` остаётся только у сессий, где действительно есть биометрия для анализа; camera guidance-only results вместо неё показывают пояснение, что интерпретация доступна при использовании BLE-пульсометра. Когда кнопка доступна, экран локально запрашивает `POST /api/communicator/v2/practice-interpretation` через STANDARD-модель и заменяет таблицу/графики текстовой интерпретацией прямо в модальном окне; если backend origin вернул HTML вместо JSON, клиент теперь явно диагностирует это как отсутствие/недоступность server route на выбранном deployment, а не как «непонятный текст ошибки».

- Экспортируемые типы/константы для каталога и роутов: **`BreathPracticeId`**, **`Chakra`**, **`BREATH_PRACTICES`**, **`isChakra`**, и т.д. (`modules/breath/index.ts`).

## 4. Конфигурация и параметры

- **Виды практик в UI:** `PRACTICE_GROUPS` — «Медитации», «Дыхание», «Асаны»; в БД для асан используется **`kind = 'yoga'`** (соглашение: в продукте «Асаны», в схеме — `yoga`).

- **Медитация:** одна статическая карточка, slug `sacred-symbol-stream`; пользовательский диапазон в каталоге/карточке и у ассистента — **1–5 минут**; дефолт launch в **`catalog.ts`** остаётся **3 мин**, а экран **`SacredSymbolStreamScreen`** при отсутствии params использует **5 мин** — расхождение дефолтов зафиксировано в `history.md`.

- **Дыхание:** семь типов (`coherent`, `nadi-shodhana`, `surya-bhedana`, `chandra-bhedana`, `square`, `triangle-up`, `triangle-down`); описания и group titles каталога — **`getPracticeCatalogStrings(locale)`** (RU/EN inline + typed overlays de–nl). Счётчики и footer каталога: gate-synced шаблоны **`practiceCountOne`**, **`practiceCountWithTotal`** (`{count}`), **`catalogFooterTemplate`** (`{total}`); **`getPracticeCatalogStrings`** собирает `practiceCount`/`catalogFooter` из overlay + для EN при `count === 1` — `practiceCountOne`. Empty/late-loading/hint copy каталога — typed поля **`emptyPracticesHint`**, **`yogaLateLoadingTitle`**, **`invalidChakraFilterHint`** (используются в **`PracticeCatalogScreen`**, без hardcoded RU в JSX).

- **Assistant entry:** default marker `id="default"` на сервере резолвится в coherent breathing 600 секунд с чакрой дня; в UI пользователь может поменять duration/chakra перед стартом через общий `PracticeCard`. Если пользователь просит **короткую / минимальную** практику без явного числа минут, серверный валидатор (`markers.ts`) берёт нижнюю границу каталога для уже названного типа: медитация 1 мин, дыхание 5 мин, асаны 20 мин.

- **Йога:** каталог асан теперь читается из **build-time snapshot** `modules/practices/data/yoga-catalog.snapshot.json` (сырые строки `practices` с `kind = 'yoga'`, `is_active = true` и embedded `practice_chakras`), зашитого в бинарь. Сетевой запрос к Supabase при открытии каталога больше не выполняется; snapshot обновляется build-скриптом `npm run update-practice-catalog-snapshot` (prepend-нут во все build-скрипты) — при изменении количества практик в БД новый snapshot попадает в приложение со следующим билдом. Локализованные поля jsonb (`title`, `description`, …) читаются через **`localizedText`** по активному `AppContentLocale` (`asContentLocale`, fallback en → ru); заголовок асаны затем проходит через общий helper **`resolveYogaPracticeTitle(...)`**. Он единообразно убирает импортный Vimeo-хвост (`_и3`, `_i3`, …), а префикс до двоеточия заменяет на locale-native **`yogaTitlePrefix`** из `getPracticeCatalogStrings(locale)` (`Практика`, `Practice`, `Übung`, …). Тот же helper использует и `app/asana-practice.tsx`, чтобы каталог и экран асаны не расходились по алгоритму имени.

- **Сессии и контекст:** в `context` JSON кладутся продуктовые поля (`source`, `launch_source`, `practice_kind`, для асан — `vimeo_id` и т.д.) для аналитики и ассистента.
- **Ожидающая практика вкладки «День»:** незавершённая карточка хранится не в `practice_sessions`, а в `day_practice_offers` (одна `pending` row на `user_id + local_date`). Источник offer — ручной выбор на вкладке или callback `Communicator.onPracticeOffered(...)` при ассистентской `PRACTICE_PICK`-карточке. На `app/(tabs)/day.tsx` выбор/отмена **оптимистичны** (карточка сразу из выбранного `PracticeSummary`; сеть в фоне, без полного reload плана). Завершённые практики по-прежнему попадают в отчёты только через `practice_sessions`; `GET /api/day` автоматически считает pending offer завершённым, если в тот же локальный день есть completed `practice_sessions` с тем же `practice_slug` (без требования `started_at >= offer.created_at` — иначе re-save offer после remount/cancel+reinsert оставлял карточку «висящей»).

- **Дыхание без пульсометра (`sensorMode: "none"` / «без пульсометра»):** `CoherenceBreathScreen` не монтирует `FingerPpgCameraSource` (фонарик и камера не включаются); ведение идёт через эмулированный пульс. Экран результатов: заголовок «Практика завершена» + рекомендация про камеру/Polar H10 + «Закрыть» (без метрик/графиков). **Камера:** «Ваши показатели» + белый комментарий + график пульса + **R–R интервалы** (display-only тахограмма: при guidance-only `beatTimestampsMsAnalyzed` пуст — биты копятся из live `mergedBeats` через `appendNewerBeatsForRrChart`; без блока длительность/когерентность/… и без debug «Шкала времени»). **BLE:** заголовок + метрики + графики, включая R–R под пульсом из `beatTimestampsMsAnalyzed` (без debug «Шкала времени»). R–R строится `buildRrIntervalChartSeries` и **не** участвует в расчёте RMSSD/stress/coherence.

## 5. Известные ограничения

- **Vimeo на экране асан:** выбор «телефон/ТВ» перенесён с экрана асаны на уровень карточки практики — карточка асаны всегда несёт две кнопки «Открыть на телефоне» и «Открыть на ТВ». **Телефон** (`app/asana-practice.tsx`) — единый телефонный режим: **iOS** — `html`+`baseUrl` (`vimeoEmbedHtml`); **Android** — URI на `https://zamkovoi.yoga/asana-embed.html` (`web_cabinet/asana-embed.html`, деплой на корень сайта), иначе fallback html+`originWhitelist:*`. `vimeoId` передаётся в launch params, чтобы не мигать «нет Vimeo ID» до загрузки metadata. Строки экрана — **`getAsanaScreenStrings`** (typed overlays для de/fr/it/es/pt/nl). **ТВ** — Remote Play через `modules/remote-play` (`useRemotePlay`, роуты `connect-tv` / `tv-remote`, таблица `tv_sessions`); «Открыть на ТВ» (хук `useAsanaRemotePlayLauncher`) при отсутствии связи открывает `/connect-tv`, при подключённом ТВ — `playVimeo(vimeoId, audiotrack)` и `/tv-remote`. Ссылки на ТВ-страницу локализованы через **`tvPageUrl`**. Embed URL жёстко `?audiotrack=<slug>` без других query-параметров; slug = `ru` для русской локали, `en` для остальных (`vimeoAudiotrackForLocale`). При отсутствии `video_external_id` телефон-режим показывает пояснение, ТВ-путь алертит «Видео недоступно». Под плеером — только кнопка «Завершить практику»; завершение и ✕ открывают общий `PracticeStopConfirmDialog` (те же строки, что у дыхания/медитации), по подтверждению — запись сессии и переход `assistant|day → /day`, иначе `router.back()`. **ТВ-страница `https://zamkovoi.yoga/tv/`** берёт язык интерфейса из `?l=` в ссылке из приложения (голый `/tv/` → `ru`); колонка `tv_sessions.locale` удалена, `audiotrack` остаётся. **Окно подключения ТВ** (`/connect-tv`) не автосабмитится на 4 символах — только по кнопке «Подключить»; после успеха между полями и кнопкой выводится диагностическое сообщение («ТВ подключен»). Если `/connect-tv` открыт с параметрами практики (`vimeoId`, `title`, `durationSec`, `audiotrack` — передаются хуком `useAsanaRemotePlayLauncher`/`onRemotePlay` каталога при отсутствии связи), кнопка после подключения меняет подпись на **«Начать практику»** → `remotePlay.playVimeo(vimeoId, audiotrack)` + `router.replace("/tv-remote", { vimeoId, title, durationSec, audiotrack })`: окно подключения закрывается, на ТВ-браузере запускается видео, на телефоне открывается пульт. Без параметров практики кнопка остаётся «Закрыть» и закрывает окно как ✕. **Экран пульта ТВ** (`/tv-remote`, обычный push-роут `headerShown: false`) построен на том же шелле, что и `app/asana-practice.tsx` — `StackScreenLayout` + `StackScrollView` + `SurfaceCardView tone="elevated"` + `FloatingCloseButton` (не `ModalScreenLayout`: на устройстве модальный шелл + карточка с `content flex:1` не рендерил `<Text>` — текст был невидим, хотя `View`-дети и кнопка ✕ рисовались; push-шелл со `StackScrollView` эту проблему не воспроизводит). Показывает «ТВ-пульт · код …», заголовок практики, «Откройте на телевизоре или на компьютере страницу https://zamkovoi.yoga/tv/», прогресс-бар, статус-пилюлю (статус локализован: `playing→запущено / paused→пауза / stopped→остановлено / waiting→ожидание / closed→закрыто`, не сырой английский), и две кнопки управления + «Отключить ТВ». **✕ и «Стоп»** открывают общий `PracticeStopConfirmDialog` (строки `getCoherenceBreathStrings(locale)` — те же, что у телефонной асаны/дыхания/медитации: «Завершить практику?» / «Завершить» / «Продолжить»); по «Завершить» — `confirmFinish` маршрутизирует по `pendingAction`: **`stop`** (✕ или «Стоп») → `remotePlay.stop()` (best-effort) + `maybeRecordTvSession()` + `router.back()` (видео на ТВ стоп, **pairing сохраняется**, возврат в Каталог/День/коммуникатор); **`disconnect`** («Отключить ТВ») → `stop()` + `maybeRecordTvSession()` + `remotePlay.disconnect()` + `router.replace("/connect-tv", { …params })` (pairing разрывается, переход в окно подключения). По «Продолжить» — диалог закрывается, практика продолжает играть. Состояние `finishing` блокирует повторный нажатие и переключает `finishLabel` на `finishingButton` («Завершаем…»). **Запись `practice_sessions` (ТВ)**: `maybeRecordTvSession` пишет строку **только если практика дошла до конца** — `durationSec` известен и `elapsedSec >= durationSec - COMPLETION_TAIL_SEC` (`COMPLETION_TAIL_SEC = 10` сек — покрывает пользователей, закрывающих вкладку на финальных общих словах; для `durationSec ≤ 10` fallback `0.9 * durationSec`); иначе запись не создаётся (ранняя остановка/прерывание не учитываются в отчётах). Идемпотентна через `recordedRef` — даже если сработает и auto-record при потере связи, и `confirmFinish`, строка пишется однократно; сбрасывается в `replay()`. `context`: `{ source: "asana", launch_source, practice_kind: "yoga", vimeo_id, playback_mode: "tv", audiotrack }`, `completionPct: 100`, `chakraFocusIds` из `chakraIds`, `startedAt = endedAt − elapsedSec·1000`; best-effort (ошибка проглатывается). **Потеря связи с ТВ** (вкладка браузера закрыта / ТВ выключен → сниппет PATCHает `status="closed"` на `beforeunload` → `isTvSessionActive` false → `session` null): экран детектит переход connected → null (`wasConnectedRef`) и вместо застывших disabled-кнопок показывает панель **«Связь с ТВ потеряна»** + подсказку + кнопку **«Подключить ТВ заново»** → `router.replace("/connect-tv", { …params })` (параметры практики прокидываются, поэтому после ввода нового кода и подключения снова появляется «Начать практику» → `playVimeo` запускает ту же практику на новой ТВ-вкладке); одновременно при потере связи вызывается `maybeRecordTvSession` (если практика была досмотрена — она засчитается, даже если пользователь не нажимал «Завершить»). Параметры `{ vimeoId, title, durationSec, audiotrack, practiceId, slug, chakraIds, launchSource }` прокидываются через весь ТВ-путь: хук `useAsanaRemotePlayLauncher(strings, launchSource)` (коммуникатор — `"assistant"`) / `onRemotePlay` каталога (`"catalog"`) → `/connect-tv`|`/tv-remote` → `ConnectTVScreen.startPractice` → `/tv-remote` → `TVRemoteScreen.disconnect` → `/connect-tv`. **Таймер `elapsedSec`** аккумулирует секунды только пока `status === "playing"` (замораживается на паузе/стопе, сбрасывается в `replay()`) — используется и для прогресс-бара, и как сигнал «дошёл до конца» для записи сессии. **Конечный автомат пульта**: главная кнопка динамическая по `status` — `stopped` → **«Запустить заново»** (`remotePlay.playVimeo(params.vimeoId, params.audiotrack)` + сброс `elapsedSec`/`recordedRef`), `paused` → «Продолжить» (`resume`), иначе → «Пауза» (`pause`); **Пауза/Продолжить/Запустить заново** работают без подтверждения. `stopRemotePlayback` больше не стирает `vimeo_id` (раньше после стопа `resume()` не монтировал плеер на ТВ — сниппету нужен `vimeo_id` в ветке `status==="playing" && next.vimeo_id`, и пульт залипал: «Пауза» залочена, «Стоп» no-op, перезапустить нельзя). Кнопка **«Отключить ТВ»** теперь тоже открывает `PracticeStopConfirmDialog` (через `requestDisconnect` → `pendingAction="disconnect"`); после подтверждения — `stop` + `disconnect` + `/connect-tv` (pairing разрывается), без подтверждения — ничего не происходит. **Кнопки в `PracticeStopConfirmDialog`** (медитация/дыхание/асаны) центрированы с небольшим интервалом — `AppDialog.actionsRow` использует `justifyContent: "center"` + `gap` (было `space-between` → разлетались к краям).

- **Медитация:** нет записи биометрических метрик в `practice_sessions.metrics` (в отличие от дыхания).

- **`user_practice_preferences`:** триггер в БД обновляет строки при вставке/обновлении `practice_sessions` с **непустым `practice_id`**; клиент передаёт **`practice_id` только для асан**; дыхание и медитация пишут в основном **`practice_slug`** без UUID — предпочтения по UUID-практикам для них триггером не ведутся.

- Полная схема БД и RLS: **`supabase/migrations/20260423080000_init.sql`** (`practices`, `practice_chakras`, `practice_sessions`, `user_daily_stats`), **`supabase/migrations/20260429051600_calibration_dialogue_orchestrator.sql`** (`user_practice_preferences` и триггеры).

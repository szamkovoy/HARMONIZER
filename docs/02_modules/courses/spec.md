## 1. Назначение

Последовательная выдача учебных материалов независимо от тарифа. Первый пилот — «Месяц здоровья»: восемь материалов и восемь писем, включая два бонуса каталога. Второй продукт — «Месяц наслаждений» (`month-pleasure`): 7 материалов (5 основных + 2 каталожных бонуса), 8 писем, включая завершающее без урока; утверждённые MD/JSON — `content/courses/month-pleasure.{review.md,json}`, импорт `20261118040000`. Продажи и выдача после оплаты ещё не подключены; обычное прохождение автоматически создаёт вебинарный пропуск.

«Месяц силы» (`month-strength`) импортирован миграцией `20261118060000`: 7 материалов (5 основных + 2 существующих бонуса), 8 писем, 8 видео. Утверждённые источники — `content/courses/month-strength.{review.md,json}`. Интервалы `[0,2,7,3,4,3,4]`, последняя выдача D23, обычное завершение показа D26/письмо в 07:00, доступ D113 (90 дней после последнего урока подтверждены Сергеем), вебинарное окно обычного прохождения D28. Собственная PNG-шапка 530×125 на email CDN, `align=center`. Тест только prepared; импорт не менял мобильный код и не запускал отправки.

## 2. Публичный контракт

- `GET /api/courses`, Bearer JWT: собственные начатые прохождения. `prepared` не показываются. Ответ `{courses: CourseView[]}`, без HTTP-кэша. Порядок — started_at DESC (начало покупки/прохождения), затем created_at/id DESC для стабильности; один порядок для «Дня» и всей истории Профиля.
- `GET /api/courses/:enrollmentId?lessonId=…`: собственное прохождение и выбранный уже открытый материал. Чужой ID/будущий урок → 404; после срока доступны только сведения о прохождении, без текста, видео и списка уроков.
- `CourseView` в `_legacy_web/shared_core/courses.ts`: даты доступа/показа, состояние, текущий урок, перечень открытых уроков, общее число материалов `totalLessons` (без будущих названий), ближайшая граница обновления. Будущие заголовки и материалы сервер не отдаёт.
- `POST /api/admin/courses/tests`, только `requireAdmin`: `action=prepare,email,courseSlug?` создаёт ожидающий тест выбранного продукта (без courseSlug — совместимый default month-health) (повторная подготовка возвращает его же); `action=start,id,confirmStart=true,testMode?` запускает (default content, явный timed для проверки календаря); prepare возвращает testMode=content/intervalSeconds=0; `action=cleanup,id,confirmCleanup=true` удаляет только выбранное тестовое прохождение.
- RPC `prepare_course_test`, `start_course_enrollment`, `start_course_content_test`, `claim_course_mail`, `finish_course_mail`, `cleanup_course_test` доступны только серверу/оператору. Прямые права anon/authenticated к трём таблицам отозваны, RLS включён.

## 3. Интерфейс

Блок курсов стоит внизу «Дня», после содержимого планировщика и кнопки итогов, с обычным межкарточным интервалом 18. В карточке полный текущий материал: курс → урок → текст/видео в авторском порядке → раскрываемые открытые уроки. Предыдущий урок заменяется при выдаче следующего. Выбор полученного урока переключает содержимое внутри карточки и прокручивает к её началу; стрелки над материалом ведут только к уже выданным урокам. Аккордеон всегда называется «Полученные уроки (N из M)» / «Полученные уроки (M уроков)». Отдельный экран `/course/[id]` из Профиля использует `FullScreenModalScaffold`, название курса и «Закрыть», без стандартного заголовка роутера. Пока `now < displayUntil`, он показывает текущий урок и закрытый список. Только при `now >= displayUntil` (последний урок больше не показывается на «Дне») открывается архив: список развёрнут, материал не выбран. Получение последнего материала само по себе не переводит интерфейс в архив. После книги в Профиле — «Мои курсы», включая истёкшие; истёкшее прохождение показывает период и объяснение повторного прохождения, без учебного содержимого.

Free получает вкладку «День» на время отображения курса, без загрузки платного планировщика. Данные курсов загружаются отдельно от Home/DayPlan, не блокируют их прогрев. Обновление — при фокусе, возврате приложения и однократным таймером на ближайшую выдачу/окончание показа/доступа; частого опроса нет. Данные разделены по auth-пользователю. Последний снимок метаданных хранится по UID (SecureStore, чанки до 1600 UTF-8 байт; web — localStorage), максимум 30 дней; текст и Vimeo ID не сохраняются. На холодном старте снимок восстанавливает известные карточки и вкладку при временном сбое; подтверждённый ответ сервера заменяет снимок, включая пустой список/отзыв. Поздний кэш не заменяет свежий ответ. GET имеет существующий сетевой retry для временных ошибок, общий дедлайн 15 секунд после получения токена, диагностическое событие без токена/ID и повтор через 15 секунд только после ошибки в foreground. При ошибке прежние сведения сохраняются; новая выдача/истёкшие даты проверяются независимо от писем. Home/DayPlan кэш не меняется.

`CourseContent` использует существующие `AppText`, `SurfaceCardView`, тему, общий `PhoneVimeoPlayer` и Remote Play. Бонус несёт ссылку на существующий `practiceId`, копии практик не создаются. Видео курса запускается по нажатию, player размонтируется при потере фокуса вкладки/экрана. Просмотр телефонного видео урока сам по себе не записывает `practice_sessions` и не открывает весь каталог.

## 4. Данные и календарь

- `courses`: продукт, сроки, связанная email-цепочка, hash авторского источника; импорт не активирует продажи.
- `course_lessons`: стабильные ID, порядок, интервалы дней, упорядоченные текстовые/видео-блоки, связь с шагом редактора писем.
- `course_enrollments`: покупатель/пользователь, source key, фиксированная IANA-зона прохождения, normal/test, prepared/active/revoked, абсолютный календарь и даты, курсор/аренда отправки. Тестов prepared/active не больше одного на пользователя/курс.

Первый урок/письмо сразу при явном запуске; следующие уроки в 00:00 местного времени, письма с 07:00. Первый однодневный переход при покупке с 18:00 переносится ещё на день; следующие интервалы считаются от предыдущего урока. Интервал ≥2 дней не увеличивается. Переходы учитывают календарь и DST. Доступ не зависит от успешной доставки письма. Зона сохраняется при подготовке и не меняется автоматически при путешествии.

Пилот: интервалы `[0,2,7,3,4,3,4,3]`, даты D/+2/+9/+12/+16/+19/+23/+26. Показ последнего материала — ещё 3 календарных дня от его выдачи; архив — 90 дней от последней выдачи (расчёт в сохранённой зоне). Новый тест по умолчанию — content: все материалы открываются при старте, письма становятся готовы сразу и последовательно отправляются одной цепочкой. Прежний timed-календарь (только по отдельному запросу): 120 секунд между материалами, письмо и доступ имеют одну назначенную дату; минутный cron может добавить до минуты к фактической отправке.

«Месяц наслаждений»: интервалы `[0,2,7,3,4,3,4]`, последние материалы D23, конец показа D26, финальное письмо D26 в 07:00, архивный доступ до D113 (90 дней после последнего урока по решению Сергея), вебинарное окно обычного прохождения до D28. Второе видео «Что дальше?» остаётся внутри последнего урока, PDF — ссылкой после задания урока 4. Восемь писем используют собственную GIF-шапку 530×135 через email CDN, `align=center`. Контент импортирован без изменения мобильного кода; запуск теста требует отдельной команды.

## Вебинарный пропуск

Миграция `20261117180000`: у обычного (`mode=normal`) активного прохождения SQL-триггер создаёт существующий `webinar_passes`, связанный уникальным `course_enrollment_id`. Начало = старт курса, конец = последняя выдача + `courses.webinar_extra_days` календарных дней в сохранённой зоне. У пилота 5 дней (D+31); мастер-класс импортируется со значением 7. Граница полуоткрытая `[valid_from,valid_until)`, учитывается время проведения вебинара. Кредиты = 1 000 000 по D5; срок остаётся реальным ограничением.

`apply_webinar_passes` принимает источником либо активный платёжный контракт, либо активное обычное прохождение. Курс используется раньше отдельного платного пропуска; существующие регистрации не перезаписываются. Публикация последующих анонсов и запись через старый клиент работают через тот же RPC. После обычного старта `startPreparedCourse` вызывает существующие приглашения `sendPassWebinarInvites` для уже опубликованных вебинаров; ошибки доставки возвращаются отдельно, доступ к урокам не откатывается. Письмо с записью использует действующую аудиторию пропусков.

Отзыв/удаление курса отзывает только его пропуск и связанные с ним регистрации. Любой тест (`mode=test`, content или timed) не выдаёт реального вебинарного пропуска и не отправляет вебинарных приглашений. При подключении оплаты запускать обычное прохождение, а при возврате отзывать его; сам checkout остаётся следующим этапом.

## 5. Письма и импорт

Общая картинка писем задаётся `emailHeader` в JSON курса (источник — строка «Шапка писем» авторского Markdown). Пилот использует предоставленную Сергеем PNG 600×232, размещённую через существующий email CDN: первый image-блок с `align=center`, ширина по колонке письма, исходные пропорции. Добавление шапки не меняет учебные тексты и расписание.

Письма хранятся в существующих `email_automation_steps`/`blocks_i18n`; редактируются обычной админкой. RU-пилот использует exact локаль → en → ru, отдельно от поведения других автоматизаций. Это письма о купленном материале без рекламного футера; complained/suppressed запрещают отправку. Несовпадение адреса/пользователя останавливает её.

`runCourseEmails` вызывается общим cron писем и отдельным защищённым `/api/cron/course-tests`. SQL precheck каждую минуту вызывает HTTP только при действительно наступившем активном тесте. Подготовленный тест не создаёт email-enrollment и не вызывает HTTP. Generic runner исключает связанные course-enrollment, поэтому шаг не отправляется двумя алгоритмами.

Claim/finish выполняются транзакционно; lease 2 минуты, Resend idempotency key `course/:enrollment/:position`, таймаут запроса 20 секунд, до пяти ошибок с последующей паузой. Пауза цепочки прекращает письма, календарь открытия сохраняется. Отмена email-enrollment прекращает последующие письма, удаление пользователя отзывает доступ. Очистка теста удаляет только его enrollment/отправки/трекеры/события и соответствующие счётчики; контакт, аккаунт, тариф и другие покупки остаются. Уже отправленные письма из почтового ящика не отзываются.

`scripts/courses-content.mjs` читает авторский `content/courses/month-health.review.md`, создаёт `month-health.json`, исходник не переписывает. `scripts/course-import-sql.mjs` создаёт SQL импорта; стабильные ID, существующие письма и уроки сохраняются, замена только через явные `--replace-emails` / `--replace-lessons` соответственно. После первичного импорта редактор БД сохраняет авторские изменения. HTML письма явно сохраняет каждую пустую строку Markdown, одиночный перевод строки остаётся `<br>`; миграция `20261118010000` исправляет только восемь известных исходных копий, не перезаписывая последующие правки. Применённый файл миграции не переписывать для будущей правки контента: генерировать новую миграцию.

## 6. Границы готовности

Реализованы тестовый серверный путь и клиентские экраны. Коммерческий checkout/повторная покупка/возврат/восстановление по почте, переводы уроков и интерфейс управления курсом в кабинете остаются последующими этапами. Отправка курса пока требует Resend; переключение общего транспорта на SES требует доработки идемпотентности курса. Реальная проверка на iPhone и команда Сергея на запуск обязательны до объявления пилота проверенным.


## Редактор уроков

`GET/PATCH /api/admin/courses/lessons/:id`, только `requireAdmin`: просмотр реальной записи `course_lessons`, сохранение `{title,blocks}` или только `{title}` без записи blocks. Редактор `/admin/courses/lessons/:id` сразу показывает отдельное поле «Название урока» и сохранение названия, независимо от темы/названия письма; затем «Редактировать»: текст Markdown и Vimeo URL/ID, добавление/удаление/порядок блоков. Проверяются название, непустой текст и Vimeo; `practiceId` бонуса сохраняется только для прежнего видео. Календарь и привязка письма этим API не изменяются. Список шагов автоцепочки возвращает `course_lesson_id` и кнопку «Урок». Для course-цепочек скрыты перестановка/удаление и delay контролы, добавление письма отключено: состав курса меняется импортом, не generic шагами.


## Уточнения после второй репетиции

Учебный текст, подпись аккордеона и названия строк списка используют `screenHint` (15/22), как рекомендация/психопрактики. После согласования 18.11 название выбранного урока и Markdown-подзаголовки используют общий `contentTitle` (16/22, weight 600); название курса остаётся `sectionTitle` (18/24). Семейство шрифта и палитры общие. Общие `SurfaceCardView`/тема сохраняют отступы и палитры. Аккордеон и список объединены без дополнительного вертикального gap; строки от 44 pt, тонкие разделители только между уроками. `CourseRowIcon` задаёт общую колонку 14 pt без внутреннего центрирования и промежуток 4 pt: стрелка/крестик 14 pt, раскрытие — тот же `day_action_chevron.png` 14×12, что у психопрактик. В Профиле перед названием курса стрелка, при отсутствии доступа нейтральный крестик; видимой подписи «Доступен» нет, отсутствие доступа озвучивается accessibility label.

Полный счётчик уроков использует явные целочисленные правила восьми локалей, без `Intl.PluralRules`: в bundled Hermes RN 0.81.5 этого конструктора нет. Прежний вызов воспроизвёл точную ошибку `Cannot read property 'prototype' of undefined` при переходе к 8/8 и открытии обоих экранов курса. Исправление проверено непосредственно в Hermes, включая все восемь локалей, и регрессионным тестом перехода частичного списка в полный/архив при отсутствующем Intl. Изменение встроенного JS требует нового билда; действующий TestFlight-бинарник сервером не обновляется (OTA не настроен).


## Универсальный импорт и завершающее письмо

`scripts/courses-content.mjs <source.review.md> <output.json>` читает метаданные/явные интервалы нового продукта, упорядоченные текстовые/видеоблоки и необязательный `## Завершающее письмо`. Точный формат — в `docs/04_workspace/courses_migration_next_practicum_prompt.md`. Неизвестные интервалы не берутся из пилота. Указанное письмо должно быть без секции урока и через три дня; в JSON это `completionEmail: {subject,markdown}`, отдельно от `lessons`. Legacy parse month-health без новых метаданных сохраняет идентичный результат; новый продукт не наследует его Vimeo/practice ID.

`scripts/course-import-sql.mjs <course.json> <new.sql>` создаёт транзакционный SQL с уникальными ID и сохраняет существующие письма/уроки по умолчанию. Новый SQL-файл нельзя перезаписать. Завершающее письмо — существующий email_automation_step в позиции после учебных писем, без course_lesson. Шапка центрирована и использует пропорции своего изображения. Удаление/смена структуры существующего курса требует явной миграции; импорт не выполняет автоматических удалений.

Миграция `20261118030000` добавляет `courses.completion_email_step_id` и снимок `course_enrollments.completion_email_step_id/completion_mail_at`. Снимок задаётся только при старте; уже начатые прохождения не дополняются задним числом. Расписание schedule содержит только настоящие уроки, поэтому CourseView/current/totalLessons, display_until, access_until и вебинарное окно не получают дополнительный материал/день. SQL проверяет принадлежность финального email_step той же цепочке и отсутствие связи с уроком. Письмо назначается на первое 07:00 сохранённой зоны не раньше display_until. Для обычного практикума с последним уроком в полночь это утро третьего календарного дня. При ошибке доставки граница показа и доступ не двигаются. Завершающее уведомление может отправиться после окончания доступа к материалам, но только у активного неотозванного прохождения; уроки при этом не возвращаются.

Курсор mail_position сначала проходит schedule.length учебных писем, затем ровно одно завершающее. finish_course_mail пишет его в общие sends/счётчики и завершает email-enrollment; сам grant остаётся active для архива. Claim/lease/идемпотентность и запрет suppressed/complained сохранены. Учебное содержимое и призыв открыть новый урок в финальное письмо не подставляются; текст задаёт автор. У такого шага в админке нет кнопки «Урок», есть подпись «без нового урока».
